# AI 使用日志

## 使用工具：Codex

## 日志 1：用户账号和问卷归属

### Prompt

> 基于 MongoDB 开发问卷系统。先实现用户账号：注册、登录、退出；用户至少保存用户名、密码、注册时间；登录用户只能看到自己创建的问卷；用户通过自己的账号创建问卷，并能进入统计页。所有问卷放在一个集合中，用户和问卷通过字段关联，不使用关系数据库。代码请按路由、服务、repository 分层，并完成这一部分的数据库接口。

### Result

AI 生成了：

- `auth/repository.py`、`auth/service.py`、`auth/guards.py`、`auth/routes.py`
- `surveys/repository.py`、`surveys/service.py`、`surveys/routes.py`
- `analytics/repository.py`、`analytics/routes.py`
- `common/db.py`、`common/errors.py`、`common/csrf.py`
- 基础登录页和问卷列表页

### 修改

- 增加用户名唯一索引和密码哈希。
- 创建、列表和统计都从登录会话取 `ownerId`，不接受前端传所有者。

## 日志 2：题目和可配置跳转

### Prompt

> 创建问卷里的题目，支持单选、多选、文本和数字。多选要能设置最少/最多选择数，文本限制字数，数字限制最大值、最小值以及是否整数；每题可以设置必选。跳转规则不能写死在程序里，要能根据单选、多选、数字答案跳到后续题目；目标题必须在后面，规则有优先级，提交时服务端要重新计算路径。不要用关系数据库，题目和规则放在问卷文档中。

### Result

AI 生成了：

- `questions/service.py`：四种题型、选项生成、答案校验、发布检查
- `logic/service.py`：规则保存、条件匹配、下一题计算、路径重放
- `templates/surveys/detail.html`：题目和规则配置界面
- `templates/publishing/public.html`：逐题填写和浏览器端跳转
- `responses/`：答卷保存和提交接口

### 修改

- 明确“必填只对访问到的题生效”，避免被跳过的必填题阻止提交这个点。
- 增加发布前校验：空问卷、悬空目标、向前跳转、无效选项全部拦截。


## 日志 3：提交、匿名和统计

### Prompt

> 补充公开填写和统计：每次提交要保存；支持多人同时填写；允许配置匿名和同一人多次填写；重复点击不能产生重复答卷。统计要支持单选每个选项人数、多选每个选项次数、文本全部内容、数字平均值，并且能查看整卷和单题统计。跳转后的统计分母不能直接用全部答卷数。

### Result

AI 生成了：

- `responses/service.py`、`responses/repository.py`、`responses/routes.py`
- `analytics/service.py` 中的四类统计
- `participantKey`、`submissionToken` 和部分唯一索引方案
- `visitedQuestionIds` 路径保存
- 统计页面的单题筛选和数字平均值显示

### 修改

- 允许重复填写时，不写入 `participantKey`，避免被唯一索引误拦截。
- 匿名身份用会话令牌哈希，不把原始 Cookie 写入数据库。
- 统计区分 `visitedCount` 和 `answeredCount`。
- 文本答案中的数字单独识别，非数字文本不参与平均值。

## 日志 7：MongoDB优化

### Prompt

> 做 MongoDB Validator + 聚合统计方向的优化，使数据库本身可以进行数据约束，修改保持局部，不要重写整个项目。

### Result

AI 增加了：

- `common/schema.py`：三个集合的 `$jsonSchema` Validator。
- `common/db.py`：启动时应用 Validator。
- `analytics/repository.py`：`$facet`、`$unwind`、`$group` 统计管道。
- `analytics/service.py`：真实 MongoDB 使用聚合，测试替身自动回退。
- `tests/mongo_integration_test.py`：Validator、聚合和 explain 测试。
- `docs/12-查询与索引证据.md`：记录实际执行结果。

### 修改

- Validator 使用 `moderate`，避免破坏已有历史文档。
- explain 在 PyMongo/MongoDB 当前组合下出现 UTF-8 解码问题；测试连接使用 `CodecOptions(unicode_decode_error_handler="replace")` 后成功得到 `EXPRESS_IXSCAN` 和 `IXSCAN`。
