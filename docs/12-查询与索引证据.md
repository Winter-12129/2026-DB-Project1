# MongoDB Validator、聚合统计与 Explain 证据

本文记录本轮针对 MongoDB 设计部分的增强和实际运行结果。

## 1. 数据库级 Validator

实现文件：

- `common/schema.py`
- `common/db.py`

应用启动并连接 MongoDB 后，会为 `users`、`surveys`、`responses`、`question_bank` 四个集合应用 `$jsonSchema` 校验器。使用：

```text
validationLevel: moderate
validationAction: error
```

这样已有的历史文档可以保留，但新的插入和合法文档更新必须符合结构。

实际验证结果：

```text
[OK] MongoDB Validator 拒绝非法 status
[OK] MongoDB Validator 拒绝缺少 versions 的题库文档
[OK] MongoDB Validator 拒绝缺少 submissionToken 的答卷
```

## 2. 聚合统计

实现文件：

- `analytics/repository.py`
- `analytics/service.py`

真实 MongoDB 下使用聚合管道：

- 单选题：`$unwind` → `$match answers.questionId` → `$group`。
- 多选题：继续展开 `answers.value`，再按选项 `$group`。
- 文本题：取回文本值，再由服务层识别数字。
- 数字题：`$avg`、`$min`、`$max`。
- 访问人数和回答人数通过 `$facet` 同时计算。

测试使用 200 条数字答卷，结果为：

```text
[OK] 聚合统计结果：
[{"_id": null, "count": 200, "average": 99.5, "min": 0, "max": 199}]
```

单元测试环境中的内存数据库没有 `aggregate` 方法，服务层会自动回退到 Python 统计；真实 MongoDB 环境使用聚合管道。

## 3. Explain 证据

运行脚本：

```powershell
python tests/mongo_integration_test.py
```

本次结果：

### shareCode 查询

```json
{
  "winningStages": ["EXPRESS_IXSCAN"],
  "nReturned": 1,
  "totalKeysExamined": 1,
  "totalDocsExamined": 1,
  "executionTimeMillis": 0
}
```

`shareCode` 使用唯一索引，返回 1 条，只检查 1 个索引键和 1 个文档。

### 答卷版本查询

```json
{
  "winningStages": ["FETCH", "IXSCAN"],
  "nReturned": 200,
  "totalKeysExamined": 200,
  "totalDocsExamined": 200,
  "executionTimeMillis": 1
}
```

查询使用 `surveyId + surveyVersion + submittedAt` 索引范围，扫描数量与返回数量一致，没有全表扫描。
### 共享题目查询

```json
{
  "winningStages": ["FETCH", "IXSCAN"],
  "nReturned": 1,
  "totalKeysExamined": 1,
  "totalDocsExamined": 1,
  "executionTimeMillis": 0
}
```

题目库的“共享给我”查询使用 `{ sharedWith: 1, updatedAt: -1 }` 索引。返回 1 条时只检查 1 个索引键和 1 个文档，没有全表扫描。
### 题库题目使用问卷查询

```json
{
  "winningStages": ["FETCH", "IXSCAN"],
  "nReturned": 1,
  "totalKeysExamined": 1,
  "totalDocsExamined": 1,
  "executionTimeMillis": 0
}
```

查询条件为 `ownerId + questions.sourceBankId`，使用多键复合索引 `{ ownerId: 1, questions.sourceBankId: 1 }`。用于跨问卷统计前定位候选问卷，避免扫描用户全部问卷。

## 4. 过程中遇到的问题

当前环境是 PyMongo 4.18.1 和 MongoDB 8.3.11。直接调用 `cursor.explain()` 时，客户端在解析执行计划响应时出现：

```text
bson.errors.InvalidBSON: 'utf-8' codec can't decode byte ...
```

这不是查询本身失败。解决方式是在测试数据库连接上使用：

```python
CodecOptions(unicode_decode_error_handler="replace")
```

之后 explain 可以正常返回，并得到上面的执行计划。这个处理只用于测试工具，不影响应用正常的 PyMongo 连接。
