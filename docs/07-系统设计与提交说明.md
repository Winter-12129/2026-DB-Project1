# 第二阶段系统设计与提交说明

## 基于 MongoDB 的在线问卷系统

第一阶段系统已经完成并通过验收。本文不重复第一阶段功能，只说明第二阶段新增的题目库、题目共享、版本管理、题目 ID 查询和跨问卷统计。

## 1. 第二阶段优化目标

本阶段要解决三个问题：

1. 常用题目如何在多份问卷之间复用。
2. 修改题库题目时，如何保留历史版本，同时不影响已经做好的问卷。
3. 同一道题被多份问卷使用后，如何查询它的使用范围并统计所有问卷的回答数据。

对应的设计结果是：

- 新增 `question_bank` 集合，使用“题目族 → 版本”两层结构。
- 问卷保存题目快照，并记录 `sourceBankId`、`sourceVersionId`。
- 题目族通过 `sharedWith[]` 共享给其他用户。
- 版本编辑支持创建新版本或直接覆盖当前版本。
- 新增题目 ID 查询、总体统计、分问卷统计和分版本统计。

## 3. 系统设计

### 3.1 模块变化

| 模块 | 第二阶段职责 |
|---|---|
| `question_bank/` | 题目族、别名、共享、版本、使用关系和 ID 解析 |
| `analytics/cross_survey_service.py` | 跨问卷数据合并、分问卷分析和分版本分析 |
| `questions/` | 从题库选题、来源快照、问卷另存题库后回填来源 |
| `surveys/repository.py` | 按 `questions.sourceBankId` 查询使用问卷 |
| `common/schema.py` | 题库 Validator |
| `common/db.py` | 题库唯一索引、共享索引和问卷来源索引 |
| `templates/question_bank/` | 题库管理、直接建题、ID 查询和统计页面 |

原有 `auth/`、`logic/`、`publishing/`、`responses/` 继续工作，不重写第一阶段业务。

### 3.2 第二阶段处理流程

题目进入题库：

```text
用户直接新建题目
或把问卷题目另存到题库
→ 规范化题干
→ 查找或创建题目族
→ 生成或复用版本
→ 返回 familyId + versionId
```

题目加入问卷：

```text
从题库选择任意版本
→ 复制题干、题型、选项、配置
→ 写入 surveys.questions[]
→ 记录 sourceBankId + sourceVersionId
```

修改题库题目：

```text
选择基础版本
→ 用户选择创建新版本或直接覆盖
→ 更新 question_bank
→ 问卷继续使用自己的题目快照
```

跨问卷统计：

```text
输入题目族 ID / 版本 ID / 问卷题 ID
→ 定位题目族和版本
→ 查询当前用户使用该题目的问卷
→ 映射每份问卷的本地题目 ID
→ 读取 responses.answers
→ 生成总体、分问卷、分版本结果
```

## 4. MongoDB 设计

### 4.1 集合关系

第二阶段新增 `question_bank` 后，四个业务集合的关系为：

```text
users
├─ _id → surveys.ownerId
└─ _id → question_bank.ownerId

question_bank
└─ versions[].id → surveys.questions[].sourceVersionId

surveys
└─ _id → responses.surveyId
```

这里仍然是应用层文档引用，不使用关系数据库外键和 JOIN。

### 4.2 嵌套结构说明

| 集合 | 嵌套位置 | 保存内容 | 用途 |
|---|---|---|---|
| `question_bank` | 文档根层 | 题目族标题、别名、共享用户、当前版本 | 维护题目身份和访问关系 |
| `question_bank` | `versions[]` | 完整的题干、题型、选项、配置、版本号、父版本 | 保存可复用题目历史 |
| `surveys` | `questions[]` | 当前问卷使用的题目快照、来源题目族和版本 | 保证问卷内容稳定 |
| `responses` | `answers[]` | 问卷本地题目 ID、题型和答案 | 保存每次实际回答 |
| `responses` | `visitedQuestionIds[]` | 服务端重放得到的访问路径 | 计算跳转题目的访问和回答分母 |

题目族示例：

```text
question_bank
├─ ownerId
├─ familyKey
├─ title
├─ aliases[]
├─ aliasKeys[]
├─ sharedWith[]
├─ currentVersionId
└─ versions[]
   ├─ id
   ├─ number
   ├─ fingerprint
   ├─ title
   ├─ type
   ├─ options[]
   ├─ config{}
   ├─ parentVersionId
   └─ createdAt
```

问卷中的来源快照：

```json
{
  "id": "q_xxx",
  "title": "你的年龄",
  "type": "number",
  "sourceBankId": "题目族 ObjectId 字符串",
  "sourceVersionId": "ver_xxx"
}
```

### 4.3 版本模型

题库只保留“题目族 → 版本”两层，不增加第三个变体层。

| 字段 | 作用 |
|---|---|
| `familyKey` | 规范化题干形成的题目族键 |
| `fingerprint` | 题型、选项文字和配置组成的内容指纹 |
| `versions[].number` | 版本展示编号 |
| `parentVersionId` | 新版本从哪个版本修改而来 |
| `currentVersionId` | 当前默认版本 |
| `sourceVersionId` | 问卷实际使用的题库版本 |

同一版本 ID 可以出现在多份问卷中。问卷保存的是快照，不直接引用题库内容，因此题库新增、覆盖或恢复版本都不会改变已有问卷。

### 4.4 新增索引

| 集合 | 索引 | 用途 |
|---|---|---|
| `question_bank` | `{ ownerId: 1, familyKey: 1 } unique` | 防止同一用户重复创建题目族 |
| `question_bank` | `{ ownerId: 1, aliasKeys: 1 }` | 按别名查找题目族 |
| `question_bank` | `{ sharedWith: 1, updatedAt: -1 }` | 查询共享给用户的题目 |
| `surveys` | `{ ownerId: 1, questions.sourceBankId: 1 }` | 查询题目被哪些问卷使用 |

`questions.sourceBankId` 使用多键索引。真实 MongoDB 的 Explain 结果为 `IXSCAN`，返回 1 条时只检查 1 个索引键和 1 个文档。

### 4.5 MongoDB Validator

题库 Validator 要求文档包含：

- 题目所有者、规范化题干键和展示标题。
- 别名、共享用户、当前版本和时间字段。
- 至少一个 `versions[]` 元素。
- 每个版本包含 `id`、编号、指纹、题干、题型、选项、配置、父版本和创建时间。

缺少 `versions` 的题库文档会被数据库直接拒绝。

## 5. API 说明

### 5.1 页面接口

| 路径 | 方法 | 作用 |
|---|---|---|
| `/question-bank` | GET | 查看自己的题目和共享给当前用户的题目 |
| `/question-bank/new` | GET/POST | 直接创建常用题目 |
| `/question-bank/<familyId>/versions/new` | GET/POST | 创建版本或直接修改版本 |
| `/question-bank/<familyId>/versions/<versionId>/restore` | POST | 切换当前版本 |
| `/question-bank/<familyId>/share` | POST | 按用户名共享 |
| `/question-bank/<familyId>/unshare` | POST | 取消共享 |
| `/question-bank/<familyId>/aliases` | POST | 添加题目别名 |
| `/question-bank/<familyId>/delete` | POST | 删除自己的题目族 |
| `/question-bank/lookup` | GET | 按题目 ID 查询 |
| `/question-bank/insights/<题目ID>` | GET | 使用问卷与跨问卷分析 |
| `/surveys/<surveyId>/questions/from-bank` | POST | 从题库复制版本到草稿问卷 |

所有写操作要求登录和 CSRF token。被共享用户只能读取和引用题目，不能修改原题目族。

### 5.2 版本保存

创建新版本和直接修改共用：

```text
GET/POST /question-bank/<familyId>/versions/new
```

表单字段：

| 字段 | 说明 |
|---|---|
| `base_version_id` | 当前编辑的基础版本 |
| `save_mode=new` | 保留旧版本并创建新版本 |
| `save_mode=replace` | 覆盖基础版本，不新增版本 |
| `type` | 题型 |
| `title` | 题干 |
| `options` | 选项，每行一个 |
| `config` 相关字段 | 多选数量、文本长度、数字范围等 |

`replace` 不改变已经进入问卷的题目快照。

### 5.3 题目 ID 查询

`/question-bank/lookup?question_id=...` 支持：

| 输入 | 含义 |
|---|---|
| 24 位 ObjectId | 题目族 ID，统计所有版本 |
| `ver_xxx` | 指定题库版本 |
| `q_xxx` | 问卷中的本地题目 ID，通过来源字段回到题库版本 |

查询成功后会跳转到：

```text
/question-bank/insights/<题目ID>
```

### 5.4 跨问卷 JSON API

```text
GET /api/v1/question-bank/insights/<题目ID>
```

返回结构示例：

```json
{
  "referenceType": "family",
  "family": {
    "id": "题目族 ID",
    "title": "你的年龄"
  },
  "usageCount": 4,
  "surveyCount": 4,
  "answeredCount": 9,
  "visitedCount": 9,
  "answerRate": 100.0,
  "usages": [
    {
      "surveyId": "问卷 ObjectId 字符串",
      "localQuestionId": "q_xxx",
      "sourceVersionId": "ver_xxx",
      "submittedCount": 3,
      "answeredCount": 3
    }
  ],
  "typeGroups": [],
  "versionBreakdown": []
}
```

返回内容包括：

- 使用问卷 ID 和问卷标题。
- 每份问卷使用的版本和本地题目 ID。
- 总体提交、访问、回答和回答率。
- 分问卷、分版本的答题分析。
- 单选题和多选题的选项分布。
- 数字题的描述统计和区间分布。
- 文本题的数量、高频值、长度和可识别数字分析。

API 只返回当前用户自己问卷的数据，不因题目共享而暴露其他用户答卷。

## 6. 关键逻辑说明

### 6.1 题目去重与别名

题目族使用规范化题干匹配，处理方式为 Unicode NFKC、转小写、去空白和标点。版本指纹使用题型、选项文字和配置，不直接使用运行时选项 ID。

“姓名”和“你的名字是”不自动做模糊合并，而是由用户添加别名。这样可以避免把语义相近但实际不同的问题错误合并。

### 6.2 版本创建与覆盖

创建新版本：

```text
v2.parentVersionId = v1.id
v2.number = 当前最大编号 + 1
currentVersionId = v2.id
```

直接覆盖：

```text
保留原 version.id、number、parentVersionId
更新题干、题型、选项、配置和 fingerprint
currentVersionId 不因编辑其他历史版本而自动改变
```

### 6.3 题目共享

共享只建立访问关系：

```text
question_bank.sharedWith[] 保存被共享用户 ObjectId
```

被共享用户可以查看和引用题目，并查看自己问卷中的使用情况；题目所有者仍掌握版本修改、删除和共享权限。

### 6.4 问卷快照与来源回填

问卷从题库选题时复制完整题目内容，同时记录：

```text
sourceBankId
sourceVersionId
```

从问卷另存到题库时，系统会把生成的题目族 ID 和版本 ID 回填到原问卷题目。这样无论题目是从题库引入，还是从问卷保存到题库，后续都能被跨问卷统计找到。

### 6.5 跨问卷映射

同一道题在不同问卷中有不同的本地题目 ID，不能直接用一个 `questionId` 查询所有答卷。系统执行两级映射：

```text
题库 familyId / versionId
→ surveys.questions[].sourceVersionId
→ 该问卷的 questions[].id
→ responses.answers[].questionId
```

统计时按问卷版本读取 `responses`，再根据题目类型合并答案。不同版本的选项 ID 可能不同，因此选择题按规范化选项文字合并。

### 6.6 跨问卷统计指标

选择题：

- 每个选项的选择次数和回答者比例。
- 多选题总选择次数和人均选择数。

数字题：

- 有效数量、平均值、中位数、标准差。
- 最小值、最大值、极差。
- 25%、75%、90% 分位数。
- 区间直方图。
- 整数和小数数量。

文本题：

- 答案数量、不同内容数和平均长度。
- 高频答案。
- 全部文本答案。
- 能识别为数字时的平均值和中位数。

同时按问卷和版本分别汇总，避免只有总体结果而无法判断数据来源。

### 6.7 权限和只读保护

- 已发布问卷禁止添加、删除或修改题目。
- 非所有者不能管理问卷或查看统计。
- 被共享用户不能修改原题目族。
- 跨问卷统计只统计当前用户自己的使用问卷。
- 题目 ID 不存在或无权访问时返回 404。
- JSON API 未登录时返回 401。
