# 基于 MongoDB 的在线问卷系统

## 系统设计、实现与提交说明

项目版本：课程项目提交版  
完成日期：2026-10-20  
项目目录：`survey-system/`

## 1. 项目说明

### 1.1 项目定位

本系统实现一个简化版在线问卷工具。
项目重点放在三件事上：
- MongoDB 中的嵌套文档怎么组织，才能同时支持题目、选项、跳转规则和答卷。
- 跳转规则怎样从程序里的 `if/else` 变成用户可配置的数据。
- 有跳转、匿名和重复填写的情况下，必填校验、答卷保存和统计分母如何保持一致。

### 1.2 用户角色

| 角色 | 主要操作 |
|---|---|
| 未登录访问者 | 打开公开链接；若问卷要求登录，则先跳转登录 |
| 注册用户 | 注册、登录、退出；创建和查看自己的问卷 |
| 问卷所有者 | 添加题目和跳转规则、发布、设置截止时间、关闭问卷、查看统计 |
| 填写者 | 按题目顺序填写，根据规则跳转，提交答卷 |

问卷所有者的权限在服务端判断，不依赖页面是否显示按钮。即使直接构造请求，非所有者也不能修改问卷或查看统计。


### 1.3 前后端版本

| 层次 | 技术或版本 | 用途 |
|---|---|---|
| 后端语言 | Python 3.12.8 | 业务逻辑、路由、答题校验和统计 |
| Web 框架 | Flask 3.1.2 | 页面路由、会话、请求和响应 |
| 数据库驱动 | PyMongo 4.18.1 | 连接 MongoDB、读写文档 |
| 模板引擎 | Jinja2 3.1.6 | 服务端渲染 HTML 页面 |
| WSGI 组件 | Werkzeug 3.1.5 | Flask 依赖的请求处理和密码哈希 |
| 数据库 | MongoDB 8.3.11 | 保存用户、问卷和答卷 |
| 前端 | HTML5、CSS3、原生 JavaScript | 页面结构、样式、逐题填写和跳转 |
| 测试 | Python `unittest`、requests | 单元测试和 HTTP 集成测试 |

前端没有使用 React、Vue 或额外构建工具。问卷页面主要由 Jinja2 渲染，题目切换、表单校验和公开填写页的即时跳转由原生 JavaScript 完成。这样减少了构建步骤，也方便直接查看一个请求从浏览器到 Flask 再到 MongoDB 的完整过程。

## 2. 系统设计

### 2.1 总体结构

```text
浏览器
  ├─ 创建者页面：注册、登录、问卷管理、统计
  └─ 公开填写页面：逐题作答、规则跳转、提交
          │
          │ HTTP / JSON
          ▼
Flask 路由层
  页面路由、JSON API、会话、CSRF 校验
          │
          ▼
业务服务层
  问卷、题目、跳转、提交、统计
          │
          ▼
Repository 层
  按模块集中 MongoDB 查询
          │
          ▼
MongoDB
  users / surveys / responses
```

路由层没有直接写 MongoDB 查询。问卷查询集中在 `surveys/repository.py`，答卷写入集中在 `responses/repository.py`，统计读取集中在 `analytics/repository.py`。这样做**是为了让题目、跳转和统计逻辑可以独立测试。**

### 2.2 模块划分

| 模块 | 目录 | 职责 |
|---|---|---|
| 公共基础 | `common/` | 数据库连接、错误、CSRF、时间、随机 ID、索引 |
| 账号 | `auth/` | 注册、登录、退出、密码哈希、当前用户、所有者校验 |
| 问卷 | `surveys/` | 问卷创建、列表、状态、分享码、截止时间 |
| 题目 | `questions/` | 四种题型、选项、答案规范化和校验 |
| 跳转 | `logic/` | 规则保存、条件求值、下一题计算、路径重放 |
| 发布分享 | `publishing/` | 发布、公开链接、截止/关闭判断、匿名入口 |
| 答卷 | `responses/` | 提交令牌、重复提交限制、答卷保存 |
| 统计 | `analytics/` | 整卷和单题统计、文本和数字汇总 |

模块之间的关系是单向的：发布模块可以调用问卷、题目和跳转模块；答卷模块调用发布、跳转和题目模块；统计模块读取答卷和问卷；题目和问卷不反过来依赖发布或统计。

### 2.3 问卷状态

| 状态 | 含义 | 公开链接行为 |
|---|---|---|
| `draft` | 草稿，只有所有者能看到管理页 | 链接不可公开填写 |
| `published` | 已发布，在截止时间前可填写 | 显示填写页 |
| `closed` | 已关闭 | 显示关闭提示，不再接受提交 |

截止时间是发布状态下的有效期。问卷超过截止时间后，状态可以仍是 `published`，但公开页面会按“已截止”处理，提交接口也会拒绝。状态只由问卷模块修改。题目、答卷和统计模块不能直接把问卷状态写成 `published` 或 `closed`。

### 2.4 关键流程

创建问卷：

```text
登录 → 填写标题/说明/匿名策略/重复填写策略
→ 创建草稿 → 直接进入题目与跳转页
```

发布问卷：

```text
所有者请求发布
→ 校验问卷非空
→ 校验题目和选项
→ 校验规则目标和优先级
→ 状态改为 published
```

公开填写：

```text
打开 /survey/<shareCode>
→ 检查问卷状态和截止时间
→ 检查是否需要登录
→ 逐题作答
→ 规则命中时跳到目标题
→ 提交答案和 submissionToken
→ 服务端重放路径、校验答案、保存答卷
```

统计：

```text
所有者打开统计页
→ 校验所有者
→ 按当前 surveyVersion 读取答卷
→ 按题目类型计算统计
→ 返回整卷或指定题目的结果
```

## 3. 数据库设计

### 3.1 集合划分

系统只使用三个业务集合：

| 集合 | 保存什么 | 说明 |
|---|---|---|
| `users` | 用户账号 | 用户名、密码哈希、注册时间 |
| `surveys` | 问卷定义 | 题目、选项、规则、状态、分享码 |
| `responses` | 已提交答卷 | 答案、访问路径、提交身份、提交令牌 |

没有使用关系数据库，也没有在查询时做关系表 JOIN。`surveys.ownerId` 指向 `users._id`，`responses.surveyId` 指向 `surveys._id`，这是应用层理解的文档引用。所有者校验和统计关联在应用代码中完成。

完整的字段清单、嵌套结构示例和索引说明见 `docs/08-MongoDB-Schema.md`。

### 3.2 嵌套结构说明

问卷不是一个扁平对象。题目、选项和跳转规则按实际业务关系嵌套在问卷文档里：

```text
surveys 文档
├─ ownerId
├─ title
├─ shareCode
├─ status / version
├─ questions[]
│  ├─ id / order / type / title / required
│  ├─ options[]
│  │  ├─ id
│  │  └─ label
│  └─ config{}
├─ rules[]
│  ├─ fromQuestionId / priority
│  ├─ when{}
│  │  └─ clauses[]
│  │     ├─ questionId
│  │     ├─ operator
│  │     └─ value / values / min / max
│  └─ action{}
│     ├─ type
│     └─ targetQuestionId
└─ timestamps / settings
```

答卷的嵌套方式不同，因为答卷是“一次提交”的快照：

```text
responses 文档
├─ surveyId / surveyVersion
├─ respondentId / anonymous / participantKey
├─ submissionToken / submittedAt
├─ answers[]
│  ├─ questionId
│  ├─ type
│  └─ value（多选时是数组）
└─ visitedQuestionIds[]
```

这样安排的原因：

- 读取一份问卷时，一次查询就能得到题目和跳转规则，不需要逐个题目查库。
- 发布时可以把题目和规则作为一个整体校验。
- 选项和题目使用稳定 ID，规则引用 ID 而不是数组位置，为了防止顺序更换带来的引用错误。
- 答卷不追加到问卷文档里，避免多人同时填写时争抢同一份文档，也避免问卷文档无限增长。
- `visitedQuestionIds` 是服务端计算出的访问路径，后续统计可以区分“看见题目”和“实际作答”。
### 3.3 `users` 集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | ObjectId | 用户 ID |
| `username` | string | 用户名，唯一 |
| `passwordHash` | string | 密码哈希 |
| `createdAt` | datetime | 注册时间，UTC |

用户名有唯一索引。密码不保存明文，登录时通过哈希校验。

### 3.4 `surveys` 集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | ObjectId | 问卷 ID |
| `ownerId` | ObjectId | 创建者 ID |
| `title` | string | 标题 |
| `description` | string | 说明 |
| `allowAnonymous` | boolean | 是否允许匿名 |
| `allowMultipleResponses` | boolean | 是否允许同一身份多次提交 |
| `shareCode` | string | 分享码，唯一 |
| `status` | string | `draft`、`published`、`closed` |
| `version` | integer | 问卷内容版本 |
| `schemaVersion` | integer | 文档结构版本 |
| `startQuestionId` | string | 起始题 ID |
| `questions` | array | 题目数组 |
| `rules` | array | 跳转规则数组 |
| `deadline` | datetime/null | 截止时间 |
| `publishedAt` | datetime/null | 发布时间 |
| `closedAt` | datetime/null | 关闭时间 |
| `createdAt` | datetime | 创建时间 |
| `updatedAt` | datetime | 更新时间 |

题目的 `order` 决定默认顺序。题目 ID、选项 ID 由服务端生成，不使用数组下标。这样即使以后支持拖动排序，规则也不需要重写。

### 3.5 `responses` 集合

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | ObjectId | 答卷 ID |
| `surveyId` | ObjectId | 所属问卷 |
| `surveyVersion` | integer | 提交时的问卷版本 |
| `respondentId` | ObjectId/null | 登录用户；匿名时为空 |
| `anonymous` | boolean | 是否匿名提交 |
| `participantKey` | string/null | 同一身份限制使用的键 |
| `submissionToken` | string | 单次提交唯一令牌 |
| `submittedAt` | datetime | 提交时间 |
| `answers` | array | 规范化后的答案 |
| `visitedQuestionIds` | array | 服务端重算的访问路径 |

`participantKey` 和 `submissionToken` 解决的是不同问题：

- `submissionToken` 防止双击或网络重试造成重复记录。同一个 token 再提交，返回已有答卷。
- `participantKey` 用于“同一身份只能填写一次”。允许重复填写时，该字段为空，不参与唯一限制。

### 3.6 索引

| 集合 | 索引 | 用途 |
|---|---|---|
| `users` | `username` 唯一 | 防止重复用户名 |
| `surveys` | `shareCode` 唯一 | 分享链接定位 |
| `surveys` | `ownerId + createdAt` | 查询我的问卷 |
| `responses` | `surveyId + surveyVersion + submittedAt` | 按版本读取答卷 |
| `responses` | `surveyId + answers.questionId` | 单题统计 |
| `responses` | `surveyId + visitedQuestionIds` | 访问人数统计 |
| `responses` | `surveyId + submissionToken` 部分唯一 | 提交幂等 |
| `responses` | `surveyId + participantKey` 部分唯一 | 同一身份限制 |

部分唯一索引只对满足条件的文档生效。允许重复填写时 `participantKey` 不写入，因此不会阻止同一用户提交多份。

## 4. API 说明

### 4.1 认证和请求约定

页面路由使用 Flask session cookie 保存登录状态。所有创建者操作都要求登录，并在服务端检查所有权。

HTML 表单 POST 和 JSON 提交都需要 CSRF token：

- HTML 表单放在隐藏字段 `csrf_token` 中。
- JSON API 放在请求头 `X-CSRF-Token` 中。

错误处理：

- 页面请求返回带错误信息的 HTML 页面。
- `/api/` 开头的请求返回 JSON 错误。

统一 JSON 错误结构：

```json
{
  "error": {
    "code": "validation_error",
    "message": "这道题是必填题"
  }
}
```


### 4.2 答卷 JSON API

```text
POST /api/v1/surveys/<shareCode>/responses
Content-Type: application/json
X-CSRF-Token: <当前会话的 CSRF token>
```

请求体：

```json
{
  "answers": {
    "q1": "o_a",
    "q2": ["o_b", "o_c"],
    "q3": "文本回答",
    "q4": 20
  },
  "submissionToken": "本次填写唯一令牌"
}
```

成功响应（新答卷）：

```json
{
  "ok": true,
  "responseId": "ObjectId 字符串",
  "idempotent": false
}
```

重复 token 时返回 200，`idempotent` 为 `true`，不会新增答卷。同一身份重复提交但换了一个 token 时，返回 409。

### 4.3 添加题目表单字段

页面和接口的服务端处理使用同一套校验规则。添加题目时需要提交：

- `type`：`single_choice`、`multiple_choice`、`text`、`number`。
- `title`：题干。
- `required`：值为 `1` 时表示必选。
- 单选/多选：`options` 按行分隔。
- 多选：`min_selections`、`max_selections`。
- 文本：`min_length`、`max_length`。
- 数字：`min_number`、`max_number`、`integer_only`。

多选题至少需要一个选项，单选题至少需要两个选项。选项 ID 由服务端生成，页面不直接指定。

### 4.4 添加跳转规则

规则统一提交到：

```text
POST /surveys/<surveyId>/questions/<questionId>/rules
```

单选题字段：

- `option_id`
- `target_question_id`
- `priority`

多选题字段：

- `option_ids`（可多个）
- `match`：`any` 或 `all`
- `target_question_id`
- `priority`

数字题字段：

- `operator`：`eq`、`gt`、`gte`、`lt`、`lte`、`between`
- `value` 或 `min_value` / `max_value`
- `target_question_id`
- `priority`

`target_question_id` 使用 `END` 表示直接结束问卷。

## 5. 关键逻辑说明

### 5.1 题型校验

题型校验集中在 `questions/service.py`，路由不直接判断题型细节。

| 题型 | 规则 |
|---|---|
| 单选 | 答案必须是当前题目的某个选项 ID |
| 多选 | 去重后必须都是合法选项；检查最少/最多选择数 |
| 文本 | 去掉首尾空白；检查最少/最多字数 |
| 数字 | 转成 Decimal；检查有限、范围、整数要求 |

数字题使用 `Decimal` 做范围和整数判断，避免直接用浮点数比较。答卷中保存整数或浮点数值；统计时再次转成 Decimal 计算平均值。
必填只对实际访问到的题生效。比如第 1 题选 A 跳到第 4 题，那么第 2、3 题即使设置了必填，也不应该阻止提交。这是“必填”和“跳转”之间必须提前定死的语义。

### 5.2 跳转规则

跳转规则保存在 `surveys.rules`，不写死在 Python 代码中。规则的核心字段：

```text
fromQuestionId  从哪道题之后检查
priority        同一来源题的执行顺序
when.clauses    条件表达式
action          跳转到目标题，或结束问卷
```

当前规则执行顺序是：

1. 按 `priority` 从小到大检查。
2. 第一条匹配规则生效。
3. 没有规则匹配时按题目 `order` 进入下一题。
4. 最后一题默认结束。
5. 跳转目标必须排在当前题之后。

只允许向后跳转，这个限制适合问卷流程；如果以后要“返回上一题”，那属于页面导航，不应混进条件跳转。

### 5.3 前端跳转和服务端重放

公开填写页使用原生 JavaScript 保存当前题号和答案，点击下一题时在浏览器端计算跳转，减少不必要请求。前端校验负责即时提示，但不能作为最终依据。提交时，服务端从 `startQuestionId` 开始，按最终答案重新走一遍路径：

```text
读取当前题
→ 校验答案
→ 判断规则
→ 选择目标题或下一题
→ 记录 visitedQuestionIds
→ 到达 END
```

服务端只接受实际路径上的答案。前端伪造一个被跳过题目的答案，不会让它进入正式答卷。这个设计是路径正确性和统计分母正确性的基础。

### 5.4 重复提交与匿名

问卷有两个独立设置：

- `allowAnonymous`：是否允许匿名打开和填写。
- `allowMultipleResponses`：是否允许同一身份提交多份。

不允许重复填写时：

- 登录用户生成 `user:<用户ID>` 作为 `participantKey`。
- 匿名用户生成会话令牌，保存其 SHA-256 哈希作为 `participantKey`。
- 数据库部分唯一索引阻止同一 `surveyId + participantKey` 的第二份答卷。

允许重复填写时，不写入 `participantKey`，每次新 token 都可以保存一份新答卷。

匿名去重的边界需要说清楚：清除浏览器 Cookie 或更换浏览器后，系统会把用户当成新的匿名会话。若业务要求严格一人一份，应要求登录，不能把 Cookie 当作绝对身份。

`submissionToken` 用于处理另一种重复：用户双击提交，或者浏览器/网络层重试同一个请求。相同 token 的请求返回已有答卷，不新增记录。

### 5.5 发布前校验

发布不是只改一个状态字段。发布前会检查：

- 至少有一道题。
- 题目和选项 ID 唯一。
- 单选、多选选项数量合理。
- 规则来源题和目标题存在。
- 目标题在当前题之后。
- 条件引用的题目已经位于当前题之前。
- 操作符和题型匹配。
- 单选/多选的选项 ID 合法。
- 数字范围合法。
- 同一来源题的优先级不重复。

任何一项失败，问卷保持草稿状态，不生成可填写的公开版本。

### 5.6 统计口径

统计从 `responses` 读取当前版本的已提交答卷，不依赖问卷文档中的计数器。
单选题：

- 每个选项显示选择人数。
- `answeredCount` 是实际回答人数。
- `visitedCount` 是访问过该题的人数。
- 没有选择的选项也返回 0。
- 百分比分母使用 `answeredCount`。

多选题：

- 先读取答案数组，再逐项累计每个选项。
- 每题只对同一份答卷中的重复选项去重。
- 百分比的分母是回答该题的人数；因为一人可选多个选项，百分比之和可能超过 100%。

文本题：

- 返回全部非空文本。
- 能解析为数字的文本额外进入数字统计，返回数字数量、平均值、最小值和最大值。
- 非数字文本不会进入平均值。

数字题：

- 返回有效数字数量、平均值、最小值和最大值。

跳转问卷的统计不能直接用总答卷数当分母。某道题只被一部分路径访问时，必须用访问过该题的人数作为访问口径，用实际有答案的人数作为回答口径。这就是保存 `visitedQuestionIds` 的原因。

## 6. 安全与数据一致性

- 密码只保存哈希。
- 表单 POST 使用 CSRF token，JSON API 使用 `X-CSRF-Token`。
- 所有者操作在服务端检查 `ownerId`。
- 非所有者查看统计返回 404，避免泄露问卷是否存在。
- 分享码是服务端生成的随机字符串，不使用可预测的问卷 ObjectId。
- 提交接口先校验问卷状态、截止时间、匿名策略和当前身份，再解析答案。
- 一次答卷只插入一个文档，不把答卷追加到问卷文档，减少并发写冲突。
- 唯一索引处理同一身份重复提交和重复提交 token。
- 统计接口只对所有者开放，文本答案不默认公开给填写者。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

$env:SECRET_KEY = "请替换为随机字符串"
$env:MONGO_URI = "mongodb://127.0.0.1:27017"

.\.venv\Scripts\python.exe app.py
```
