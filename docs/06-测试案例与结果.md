# 测试案例与测试结果

测试日期：2026-10-22
测试对象：基于 MongoDB 的问卷系统  
测试环境：Windows、Python 3.12.8、MongoDB 8.3.11

## 1. 测试范围

测试覆盖账号、问卷管理、题目与题目库、跳转规则、公开填写、重复提交、版本共享、题目 ID 查询和跨问卷统计十个部分。测试分为三层：

1. `tests/test_first_feature.py`：不依赖外部数据库，使用内存数据库替身验证业务逻辑。
2. `tests/api_live_test.py`：启动真实 Flask 服务和临时 MongoDB，通过 HTTP 页面和 JSON API 走完整流程。
3. 真实 MongoDB 冒烟测试：验证 PyMongo 查询、索引、答卷写入和统计读取。

测试使用的临时数据库为 `survey_system_version_test`，测试结束后会删除，不修改日常使用的 `survey_system` 数据库。

## 3. HTTP 测试流程

`tests/api_live_test.py` 不是 Flask 内部测试客户端，而是通过真实 HTTP 请求访问运行中的 Web 服务。执行流程如下：

1. 注册共享目标用户，再注册并登录主测试用户。
2. 打开 `/question-bank/new`，直接创建一道常用题。
3. 创建问卷并添加单选、多选、文本、数字四类题目，把单选题保存到题目库。
4. 检查原问卷中自动出现 `sourceBankId` 和 `sourceVersionId`。
5. 基于 v1 创建 v2，再选择“直接修改”更新 v2，确认版本数没有增加。
6. 恢复 v1，确认历史和当前指针。
7. 把题目族共享给第二个用户，第二个用户登录并确认看到共享题目。
8. 第二个用户从共享题目中引入一个版本，检查来源快照。
9. 主用户创建第二份问卷，从自己的题库引入同一版本，并发布。
10. 给第一份问卷添加跳转规则并发布。
11. 提交两份走不同路径的答卷，再向第二份问卷提交一份答卷。
12. 用重复 token 再提交，确认幂等结果。
13. 打开 `/question-bank/insights/<题目族ID>`，检查返回两份问卷 ID、总体分析、分问卷和分版本分析。
14. 打开 `/api/v1/question-bank/insights/<题目族ID>`，检查 `surveyCount`、`answeredCount` 和 `versionBreakdown`。
15. 用版本 ID 访问 `/question-bank/lookup`，确认跳转到对应分析页。
16. 请求整卷和单题统计页面，确认来自题库的题目包含“跨问卷分析”入口。

测试输出中的每个步骤均返回 `[OK]`，最终输出：

```text
HTTP 测试全部通过。
```

## 7. 当前测试边界

以下情况还没有自动化覆盖，或需要人工验证：

- 不同浏览器之间的视觉差异。
- 大量答卷下的统计性能。
- 并发浏览器同时提交的压力测试。
- 邮件、第三方登录等尚未实现的功能。

这些边界在提交说明中也作为已知限制写明，避免把已经验证的功能和未验证的功能混在一起。
